# Pantry 0.0.1 shared-recipes plan

## Scope

Make shared recipes a truthful, secure, metadata-first core while preserving private-by-default behavior. The vertical slice covers the Worker model/API, owner/recipient authorization semantics, redacted discovery, truthful docs/UI, safe local examples, and automated authorization/isolation/failure tests. Pantry remains storage-only: it never executes recipes. `get`, `run`, push, and delete are not expanded by this slice; recipe source is returned only by the existing explicitly addressed `GET /recipe/:name` path after authorization.

## Security model

- Bearer authentication fails closed when configuration is absent; invalid credentials are `401`.
- Every credential maps to one normalized owner. Private rows are visible only to that owner.
- A recipe author may opt a row into `shared`; shared discovery exposes metadata and author provenance, never `code` or secrets.
- A recipient may discover and explicitly fetch an opted-in shared recipe, but cannot read private rows, mutate another owner’s row, or infer private existence from errors.
- Metadata is treated as untrusted public-to-recipients input: no bearer tokens, recipe source, or secret-bearing fields are serialized.
- Sharing is owner-wide for 0.0.1; recipient-specific grants, invitations, revocation, and audit trails are planned, not implemented.

## Acceptance criteria

1. Model/API clearly distinguish owner, private/shared visibility, author, and recipient read permissions.
2. Owner and multi-owner tests prove private isolation, shared opt-in, recipient reads, owner-only writes, invalid/missing auth failures, and non-enumerating `404`s.
3. List/discovery responses are metadata-only and tests reject `code`, tokens, and secret-like fields.
4. Docs and local examples demonstrate sharing with fixture credentials only and label planned capabilities honestly.
5. Mote’s UI renders truthful private/shared/unavailable states and refreshes through the native bridge without receiving credentials or source.
6. Native/web checks, API tests, and a clean real-browser proof run; no deploy or publish occurs.
